# افزودن روز کاری به تاریخ با آخر هفته‌ی ایران در Dynamics CRM (استپ Add Business Days)

**استپ Add Business Days تعداد مشخصی «روز کاری» به یک تاریخ اضافه می‌کند و روزهای آخر هفته و تعطیلات رسمی را نمی‌شمارد.** روزها به **وقت ایران** حساب می‌شوند تا روز هفته و تعطیلات با تقویمی که کاربران می‌بینند یکی باشد. آخر هفته را خودتان تعیین می‌کنید (پیش‌فرض: پنج‌شنبه و جمعه) و فهرست تعطیلات را از خود CRM با یک FetchXml می‌گیرد.

برای استفاده از این استپ، در طراحی Workflow از منوی **Add Step** گروه **MvcTeam Date & Time** را باز کنید و **Add Business Days** را انتخاب کنید.

## پارامترهای ورودی

* **DateTime Value (اجباری)** : تاریخ شروع.
* **Days to Add (اجباری)** : تعداد روز کاری. عدد **منفی** به عقب می‌شمارد. اگر `0` باشد، تاریخ شروع بدون تغییر برمی‌گردد.
* **Weekend Days (اجباری، پیش‌فرض: `4|5`)** : روزهای آخر هفته، به‌صورت شماره‌ی روز و جداشده با `|`. شماره‌ها: `0` = یکشنبه، `1` = دوشنبه، `2` = سه‌شنبه، `3` = چهارشنبه، `4` = پنج‌شنبه، `5` = جمعه، `6` = شنبه.
* **Holidays Query (FetchXml)** : یک FetchXml که فهرست تعطیلات را برمی‌گرداند (اختیاری). هر ردیفِ نتیجه باید ستونی به نام `holiday` داشته باشد که تاریخ تعطیلی است (ستون معمولی یا ستون با نام مستعار (alias) هر دو قبول است).

## پارامتر خروجی

* **Resulting DateTime** : تاریخ نتیجه (UTC). ساعت و دقیقه‌ی تاریخ شروع حفظ می‌شود.

## نحوه‌ی کار

1. تاریخ شروع به وقت ایران تبدیل می‌شود.
2. روز به روز جلو (یا عقب) می‌رود. روزی که جزو آخر هفته یا تعطیلات باشد **شمرده نمی‌شود**.
3. وقتی تعداد روز کاری کامل شد، نتیجه به UTC برمی‌گردد.
4. تاریخ تعطیلی فقط بر اساس **روز** مقایسه می‌شود (ساعتش مهم نیست). تاریخ‌های تعطیلی که CRM به‌صورت UTC می‌دهد هم به روز ایران تبدیل می‌شوند.
5. فهرست تعطیلات با دسترسی **سیستمی** خوانده می‌شود؛ پس به دسترسی کاربر اجراکننده‌ی Workflow بستگی ندارد.

## نمونه‌های واقعی

همه‌ی نمونه‌ها از چهارشنبه ۲۳ سپتامبر ۲۰۲۶ ساعت ۱۲:۰۰ UTC (۱۵:۳۰ به وقت ایران) شروع می‌شوند:

| Days to Add | Weekend Days | نتیجه (UTC) | توضیح |
|---|---|---|---|
| `1` | `4\|5` | 2026-09-26 12:00 (شنبه) | پنج‌شنبه و جمعه رد می‌شوند |
| `2` | `4\|5` | 2026-09-27 12:00 (یکشنبه) | |
| `5` | `4\|5` | 2026-09-30 12:00 (چهارشنبه) | |
| `1` | `5` | 2026-09-24 12:00 (پنج‌شنبه) | فقط جمعه آخر هفته است |
| `2` | `5` | 2026-09-26 12:00 (شنبه) | جمعه رد می‌شود |
| `1` | `6\|0` | 2026-09-24 12:00 (پنج‌شنبه) | آخر هفته‌ی شنبه و یکشنبه |
| `3` | `6\|0` | 2026-09-28 12:00 (دوشنبه) | شنبه و یکشنبه رد می‌شوند |
| `-3` | `4\|5` | 2026-09-20 12:00 (یکشنبه) | به عقب |
| `0` | `4\|5` | 2026-09-23 12:00 | بدون تغییر |
| `3` | خالی | 2026-09-26 12:00 | آخر هفته‌ی خالی یعنی همه‌ی روزها کاری است |

**با تعطیلی:** اگر شنبه ۲۶ سپتامبر تعطیل رسمی باشد و آخر هفته `4|5`، افزودن ۲ روز کاری به چهارشنبه، **دوشنبه ۲۸ سپتامبر** را می‌دهد (پنج‌شنبه، جمعه و شنبه‌ی تعطیل رد می‌شوند و یکشنبه و دوشنبه شمرده می‌شوند).

**مرز نیمه‌شب ایران:** ورودی ۲۳ سپتامبر ساعت ۲۱:۰۰ UTC در ایران ساعت ۰۰:۳۰ پنج‌شنبه است. افزودن ۱ روز کاری (آخر هفته `4|5`) نتیجه‌ی **۲۵ سپتامبر ساعت ۲۱:۰۰ UTC** را می‌دهد، یعنی ساعت ۰۰:۳۰ شنبه به وقت ایران (چون پنج‌شنبه و جمعه رد شدند).

## نوشتن Holidays Query (FetchXml)

FetchXml باید ردیف‌هایی برگرداند که ستون `holiday` تاریخ تعطیلی است. مثال ساده (موجودیتی به نام «تعطیلی» با فیلد تاریخ):

```xml
<fetch>
  <entity name="new_holiday">
    <attribute name="new_date" alias="holiday" />
  </entity>
</fetch>
```

* نتیجه‌ی چند صفحه‌ای به‌طور خودکار صفحه‌به‌صفحه خوانده می‌شود.
* اگر متن FetchXml معتبر نباشد یا اجرای آن با خطا روبه‌رو شود، استپ با پیام «Holidays Query is not valid FetchXml» یا «Holidays Query failed» متوقف می‌شود.

## خطاها

| پیام | علت |
|---|---|
| `DateTime Value is required.` | تاریخ شروع خالی است. |
| `Weekend Days can't include all seven days.` | آخر هفته همه‌ی هفت روز را شامل شده است (و Days to Add صفر نیست). |
| `Weekend Days '…' is not valid. Use day numbers 0-6 separated by '|' …` | مقدار Weekend Days شماره‌ی `0` تا `6` نیست (مثلاً `9` یا `Fri`). |
| `Holidays Query is not valid FetchXml` | متن FetchXml معتبر نیست. |

## نکته‌ها

* این استپ با استپ‌های `IsBusinessDay` و `DateDiffBusiness…` تفاوت دارد: آن استپ‌ها آخر هفته را **همیشه شنبه و یکشنبه** می‌دانند، ولی این استپ آخر هفته را خودتان تعیین می‌کنید. برای تقویم ایران از این استپ و [Business Days Between](business-days-between.md) استفاده کنید.
* برای شمردن روز کاری بین دو تاریخ از [Business Days Between](business-days-between.md) استفاده کنید؛ آن استپ عکس همین استپ است: افزودن N روز کاری به تاریخ شروع، تاریخ پایان را برمی‌گرداند.
* برای نمایش نتیجه به تاریخ شمسی از [Format Persian DateTime](../persian/format-persian-date-time.md) استفاده کنید.
