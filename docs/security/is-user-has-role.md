# بررسی داشتن نقش امنیتی توسط کاربر در Dynamics CRM (استپ Is User Has Role)

این استپ بررسی می‌کند که یک کاربر یک نقش امنیتی (Security Role) مشخص را **به‌طور مستقیم** دارد یا نه.

برای استفاده از این استپ، در طراحی Workflow از منوی **Add Step** به گروه **MvcTeam Security** بروید و **Is User Has Role** را انتخاب کنید.

## پارامترهای ورودی

* **User (اجباری)** : کاربر موردنظر (Lookup به کاربر).
* **Security Role (اجباری)** : نقش امنیتی موردنظر (Lookup به نقش).

## پارامتر خروجی

* **Is User Has Role** : اگر کاربر آن نقش را داشته باشد `True` و در غیر این صورت `False` است.

## نحوه‌ی کار

* فقط نقش‌هایی حساب می‌شوند که **مستقیماً به خود کاربر** داده شده‌اند. نقشی که کاربر فقط از طریق عضویت در یک تیم می‌گیرد شمرده نمی‌شود؛ برای آن از [Is User Teams Have Role](is-user-teams-have-role.md) استفاده کنید.
* نقش‌ها در CRM برای هر واحد سازمانی (Business Unit) یک کپی دارند. این استپ نقش را بر اساس «نقش اصلی» (Root Role) مقایسه می‌کند؛ پس اگر کاربر همان نقش را در واحد سازمانی خودش داشته باشد، حتی اگر کپی آن با نقشی که انتخاب کرده‌اید فرق داشته باشد، `True` می‌شود.
* بررسی با دسترسی **سیستمی** انجام می‌شود؛ پس حتی اگر کاربر اجراکننده‌ی Workflow اجازه‌ی خواندن نقش‌ها را نداشته باشد، درست کار می‌کند.

## نکته‌ها

* اگر User یا Security Role خالی باشد، استپ با خطای `User is required.` یا `Security Role is required.` متوقف می‌شود.
* کاربرد رایج: پیش از انجام یک کار حساس، با یک شرط (Check Condition) بررسی کنید کاربر «مدیر سیستم» یا نقش خاصی را دارد.
* برای بررسی عضویت در تیم از [Is User Member Of Team](is-user-member-of-team.md) استفاده کنید. برای گرفتن کاربری که Workflow را شروع کرده از [Get Initiating User](get-initiating-user.md) استفاده کنید.
